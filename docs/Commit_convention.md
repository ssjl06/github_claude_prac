# Commit Convention

## 커밋 메시지 구조

```
[<type>] <subject>

[body]

[footer]
```

---

## Type 종류

| Type | 설명 |
|------|------|
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `docs` | 문서 수정 (README, 주석 등) |
| `style` | 코드 포맷 변경 (로직 변경 없음) |
| `refactor` | 코드 리팩토링 (기능/버그 변경 없음) |
| `test` | 테스트 코드 추가 및 수정 |
| `chore` | 빌드 설정, 패키지 업데이트 등 기타 작업 |

---

## 규칙

1. **subject**는 50자 이내로 간결하게 작성한다.
2. **subject**는 마침표를 붙이지 않는다.
3. **subject**는 명령형으로 작성한다. (예: "기능 추가" O, "기능 추가했음" X)
4. **body**는 선택 사항이며, 변경 이유와 내용을 설명한다.
5. **footer**는 선택 사항이며, 관련 이슈 번호를 참조한다. (예: `Closes #123`)
6. **Type** 을 맨 앞에 대괄호와 함께 삽입한다

---

## 예시

```
feat: 로그인 기능 추가

이메일과 비밀번호를 이용한 로그인 기능을 구현했다.
JWT 토큰을 발급하여 세션을 유지한다.

Closes #12
```

```
fix: 메인 페이지 버튼 클릭 오류 수정
```

```
docs: README 설치 방법 업데이트
```
